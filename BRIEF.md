# Second Look: the co-signer that actually reads the paperwork

Entry for the Meta Global AI Developer Hackathon (solo, indie track). Hard deadline: Wed Nov 4, 2026, 9:00 PM ET. Build window Oct 27 to Nov 4. All code must be written during the event (new work only).

## Product
A worker types data from logistics paperwork into a system (a warehouse system, TMS or customs portal). Second Look watches the PAPER through Ray-Ban Meta glasses (Gen 1) and reads the SCREEN digitally. It catches mismatches as they're typed, blocks submit, proposes the fix, logs an audit trail, and drafts follow-ups (e.g. a damage claim from a handwritten exception).

Documents (synthetic only, no real PII or PHI): bill of lading, air waybill, commercial invoice, packing list, delivery receipt or proof of delivery, pallet label (SSCC).

Checks:
1. Field match: paper vs. typed value (digit transpositions, dropped digits, swapped fields).
2. Deterministic check digits: AWB mod-7 check digit, ISO 6346 container check digit, SSCC/GS1 mod-10. These run before any model call.
3. Cross-document: invoice qty vs. packing list, BOL weight vs. AWB, POD received vs. shipped count.
4. Handwritten exceptions on the POD ("2 cartons damaged") turn into a claim draft.

## Required Meta stack (a gate for judging)
- Muse Spark via Meta Model API (OpenAI-compatible, https://api.meta.ai/v1): reads and reasons over the documents, explains mismatches, drafts claims.
- SAM 3.1 via Meta Model API (model `sam-3.1`, POST /v1/responses): locates and crops the document and its fields in glasses frames. One noun-phrase concept per request; still frames or short MP4 clips (no live video input).
- Muse Glimmer (open weights, about 30B, runs on this Mac Studio or a cloud GPU): local first-pass match or flag, plus PII redaction before anything leaves the machine. Only disagreements escalate to Muse Spark. Targets the $10K open-weight bonus.
- Built with Muse Code.
- If using Baseten for Muse Spark Open, the model id is `meta-models/muse-spark-open-1026`.

## Glasses input
Meta Wearables Device Access Toolkit (DAT 1.0, https://wearables.developer.meta.com/docs/develop/dat/). iOS sample app CameraAccess (facebook/meta-wearables-dat-ios). Stream frames at 2 to 7 fps at 720x1280 and use the Mock Device Kit (phone camera) for development. Always keep a recorded POV-clip fallback that runs through the same pipeline.

## Screen input
Screen capture or a small browser extension on a mock warehouse-system web form. Never read the monitor through the glasses.

## Eval (technical-depth score)
About 100 synthetic forms with injected errors. Report precision, recall, latency and cost per form for a single-model baseline vs. the tiered Glimmer-to-Spark pipeline vs. a check-digit-only baseline.
